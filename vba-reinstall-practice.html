설치 구성 확인

이 화면 · Windows 데스크톱 Excel

지금 할 일

기존에 설치한 대아 업무용 VBA를 정리하고, 2026-09-23 배포 통합본으로 설치합니다. 아래에서 실제 업무용 ZIP을 받습니다.

이 작업이 필요한 이유

VBA는 반복 작업을 실행하는 코드이고, XLAM은 그 코드를 여러 업무 파일에서 사용하도록 모은 추가 기능입니다. 리본은 그 기능을 호출하는 버튼입니다. 세 가지가 연결되어야 업무에 사용할 수 있습니다.

생략하거나 다르게 하면

예전 학습용 V6·V10을 통합본에 다시 넣으면 중복되거나 이전 버전으로 돌아갈 수 있습니다. 이번에는 완성된 XLAM을 설치합니다.

완료 기준

ZIP을 내려받았고, 이번에 교체할 업무용 도구를 함께 확인했습니다.

화면이 다르거나 막힐 때

브라우저용 Excel에서는 VBA가 실행되지 않습니다. 이 페이지는 설치 안내이며 PC를 자동 조작하지 않습니다.

기존 도구 확인

Excel → 파일 → 옵션 → 추가 기능

지금 할 일

업무용 추가 기능의 이름과 위치를 적습니다. Alt+F11 → Ctrl+R에서 XLAM·PERSONAL.XLSB·업무 파일 프로젝트도 확인합니다. 기존 리본과 시트 버튼은 화면을 캡처합니다.

이 작업이 필요한 이유

코드가 추가 기능에 있을 수도, 개인용 매크로 통합문서나 업무 파일 안에 있을 수도 있습니다. 버튼이 같아 보여도 실행하는 코드는 다를 수 있습니다.

생략하거나 다르게 하면

추가 기능 하나만 제거해도 다른 곳에 남은 구버전이 계속 실행될 수 있습니다. 이름이 Module1이라는 이유만으로 삭제할 수는 없습니다.

완료 기준

교체할 파일의 정확한 경로와 관련 버튼·모듈이 기록되어 있습니다.

화면이 다르거나 막힐 때

VBA 편집기는 Alt+Q로 Excel로 돌아옵니다. 확인되지 않은 프로젝트는 삭제 대상으로 확정하지 않습니다.

리본 설정 백업

파일 → 옵션 → 리본 사용자 지정

지금 할 일

가져오기/내보내기 → 모든 사용자 지정 내보내기. 날짜를 붙인 VBA_교체전_백업 폴더에 저장합니다.

이 작업이 필요한 이유

리본 설정 파일에는 버튼 배치와 실행 연결이 들어 있습니다. XLAM을 복사하는 것만으로 메뉴 설정까지 백업되지는 않습니다.

생략하거나 다르게 하면

새 메뉴를 가져오면 기존 리본과 빠른 실행 도구 모음 사용자 지정이 바뀝니다. 백업이 없으면 이전 배치를 다시 만들어야 할 수 있습니다.

완료 기준

백업 폴더에 .exportedUI 파일이 있습니다.

화면이 다르거나 막힐 때

파일 탐색기 → 보기에서 파일 확장명을 표시하면 파일 종류를 구분하기 쉽습니다.

코드·업무 파일 백업

Excel 저장 → 모든 Excel 창 닫기 → 탐색기

지금 할 일

기록한 XLAM, 수정할 XLSM, 사용하는 경우 PERSONAL.XLSB를 백업 폴더로 복사합니다. 파일 이름·원래 경로를 메모합니다.

이 작업이 필요한 이유

백업은 설치 실패뿐 아니라 삭제 후 필요한 기능을 발견했을 때 되돌리는 기준입니다. 종료 후 복사하면 저장된 상태를 확보하고 파일 잠금도 피할 수 있습니다.

생략하거나 다르게 하면

열려 있는 파일의 저장 전 변경은 복사본에 들어가지 않을 수 있습니다. 백업을 원본과 같은 자동 실행 폴더에 두면 함께 로드될 수도 있습니다.

완료 기준

원본과 별도 위치에 백업 파일이 있고 크기가 0이 아닙니다.

화면이 다르거나 막힐 때

저장되지 않은 업무 내용을 먼저 저장합니다. 백업 폴더는 AddIns·XLSTART 밖에 둡니다.

기존 추가 기능 해제

Excel → 파일 → 옵션 → 추가 기능 → 관리: Excel 추가 기능 → 이동

지금 할 일

앞에서 교체 대상으로 확인한 기존 업무용 XLAM의 체크를 해제합니다. 확인을 누르고 Excel을 모두 닫습니다.

이 작업이 필요한 이유

체크 해제는 Excel이 해당 도구를 자동으로 불러오는 것을 중단하는 작업입니다. 먼저 연결을 끊어야 구버전과 새 버전의 동시 실행을 피할 수 있습니다.

생략하거나 다르게 하면

파일만 옮기면 Excel이 예전 위치를 찾는 메시지가 나올 수 있습니다. 체크 해제만으로 파일 자체가 삭제되지는 않습니다.

완료 기준

기존 업무용 추가 기능을 해제했고 모든 Excel 창을 닫았습니다.

화면이 다르거나 막힐 때

COM 추가 기능이나 회사의 다른 추가 기능은 이번 VBA 교체와 구분합니다. 확인한 교체 대상만 해제합니다.

구버전 설치 파일 제거

탐색기 · 기록한 구버전 XLAM 위치

지금 할 일

백업과 원본 파일을 대조한 뒤 교체 대상 구버전 XLAM을 원래 폴더에서 제거합니다. 휴지통은 비우지 않습니다.

이 작업이 필요한 이유

이 단계가 실제 설치 파일 정리입니다. 새 통합본 하나만 고정 위치에 두면 어떤 버전이 실행되는지 관리하기 쉽습니다.

생략하거나 다르게 하면

이름이 비슷한 다른 업무 파일까지 지우면 관련 자동화가 중단됩니다. 백업 없는 삭제는 복구 근거를 없앱니다.

완료 기준

교체 대상으로 기록한 구버전만 원래 위치에서 제거했고 백업은 남아 있습니다.

화면이 다르거나 막힐 때

사용 중이라면 Excel 창이 남아 있는지 확인합니다. 저장하지 않은 작업을 강제 종료하지 않습니다. 목록의 옛 항목이 남아도 비활성 상태일 수 있습니다.

중복 코드 정리

해당 XLSM 또는 PERSONAL.XLSB → Alt+F11 → Ctrl+R

지금 할 일

앞에서 확인한 중복 코드가 있는 경우만 진행합니다. 정확한 프로젝트의 전용 표준 모듈을 열어 코드 확인 → 우클릭 → 파일 내보내기 → 모듈 제거 → 저장합니다. 없으면 해당 없음으로 기록합니다.

이 작업이 필요한 이유

XLAM을 바꿔도 통합문서 안의 코드는 남습니다. 같은 실행 이름이 여러 곳에 있으면 버튼이 과거 코드를 호출하거나 이름 충돌이 생길 수 있습니다.

생략하거나 다르게 하면

Module1 등 이름만 보고 제거하면 다른 기능도 잃을 수 있습니다. 여러 기능이 섞인 모듈·Sheet·ThisWorkbook·PERSONAL 전체를 일괄 삭제하지 않습니다.

완료 기준

확인한 중복 전용 모듈만 제거했거나 해당 없음으로 기록했습니다.

화면이 다르거나 막힐 때

혼합 모듈이나 잠긴 프로젝트이면 제거를 멈추고 해당 파일과 코드 위치를 기록합니다. 삭제 범위를 분리한 뒤 이어갑니다. 통합본 자체의 모듈은 뜯어내지 않습니다.

기존 버튼 정리

Excel 리본 사용자 지정 / 업무 시트

지금 할 일

기존 업무용 사용자 지정 그룹·명령만 선택해 제거합니다. 시트 도형 버튼은 우클릭 → 매크로 지정으로 연결을 확인한 뒤 구버전용 버튼만 삭제합니다.

이 작업이 필요한 이유

버튼은 코드와 별도 객체입니다. 코드를 지워도 버튼이 남아 잘못된 파일을 계속 찾을 수 있습니다.

생략하거나 다르게 하면

전체 사용자 지정 초기화는 다른 업무 메뉴까지 지웁니다. 시트의 데이터 셀을 버튼으로 착각하지 않도록 선택 상태를 확인합니다.

완료 기준

확인한 구버전 버튼을 정리했고 데이터는 그대로입니다.

화면이 다르거나 막힐 때

추가 기능이 자동 생성한 탭은 해당 추가 기능을 해제하고 재시작하면 사라질 수 있습니다. 수동 메뉴와 구분합니다.

설치 파일 압축 해제

다운로드 폴더 · 실제 업무용 통합본 ZIP

지금 할 일

마우스 오른쪽 → 속성에서 출처를 확인하고 차단 해제가 보이면 적용합니다. 이어 모두 압축 풀기를 실행합니다.

이 작업이 필요한 이유

압축 해제는 XLAM과 메뉴 파일을 실제 폴더에 꺼내는 과정입니다. ZIP 안에서 바로 열면 임시 위치를 사용해 연결이 불안정해질 수 있습니다.

생략하거나 다르게 하면

임시 경로를 설치 위치로 사용하면 파일 정리 후 버튼이 작동하지 않을 수 있습니다.

완료 기준

압축 밖에서 매크로 신상.xlam과 메뉴 설정 파일을 확인했습니다.

화면이 다르거나 막힐 때

조직 정책으로 차단되면 담당자에게 확인합니다. 모든 매크로 허용이나 VBA 프로젝트 접근 허용을 일괄 켜지 않습니다.

추가 기능 파일 배치

Win+R → %APPDATA%\Microsoft\AddIns

지금 할 일

AddIns 폴더를 열고 새 매크로 신상.xlam을 복사합니다. 탐색기 주소창을 클릭해 실제 전체 경로를 복사하여 아래 설치 경로 칸에 기록합니다.

이 작업이 필요한 이유

AddIns는 개인용 추가 기능을 보관하기 편한 고정 위치입니다. %APPDATA%는 현재 Windows 사용자 폴더로 해석됩니다.

생략하거나 다르게 하면

다운로드 폴더에서 파일을 지우거나 이름을 바꾸면 연결이 끊깁니다. 메뉴 파일 안의 예전 사용자 경로는 자동으로 바뀌지 않습니다.

완료 기준

AddIns 안에 새 XLAM이 있고 실제 경로를 기록했습니다.

화면이 다르거나 막힐 때

폴더가 없다면 만듭니다. 기존 동명 파일이 남았다면 교체 전 백업과 구버전 해제 여부를 확인합니다.

Excel 추가 기능 등록

파일 → 옵션 → 추가 기능 → 관리: Excel 추가 기능 → 이동

지금 할 일

찾아보기 → AddIns의 매크로 신상.xlam 선택 → 해당 항목 체크 → 확인합니다.

이 작업이 필요한 이유

파일을 폴더에 복사하는 것과 Excel이 불러오게 등록하는 것은 별개입니다. 등록하면 Excel을 다시 켤 때 도구가 준비됩니다.

생략하거나 다르게 하면

등록하지 않으면 버튼은 있어도 호출할 코드를 찾지 못할 수 있습니다.

완료 기준

새 파일을 가리키는 추가 기능이 체크되어 있습니다.

화면이 다르거나 막힐 때

XLAM은 일반 통합문서처럼 시트가 나타나지 않을 수 있습니다. 화면이 안 보이는 것만으로 설치 실패라고 판단하지 않습니다.

버튼 연결 · 12 / 19

내 PC용 리본 설정

이 페이지 · 아래 메뉴 경로 도구

지금 할 일

설치한 XLAM의 실제 전체 경로를 입력합니다. 미리보기에 나온 경로를 대조한 후 이 PC용 메뉴 파일을 내려받습니다.

이 작업이 필요한 이유

기존 메뉴에는 배포 PC의 절대 경로가 들어 있습니다. 버튼의 onAction 연결을 현재 PC의 XLAM 경로로 바꿔야 합니다. 모듈명과 실행명은 유지합니다.

생략하거나 다르게 하면

파일은 설치됐는데 매크로를 실행할 수 없다는 메시지가 나오는 대표 원인입니다. %APPDATA% 문자열 대신 탐색기에서 확인한 실제 경로가 필요합니다.

완료 기준

미리보기의 경로가 실제 파일과 일치하고 이 PC용 .exportedUI를 받았습니다.

화면이 다르거나 막힐 때

경로만 바꾸는 도구입니다. 실제 파일 존재나 매크로 실행 여부를 브라우저가 검사하지는 않습니다.

리본 메뉴 적용

파일 → 옵션 → 리본 사용자 지정

지금 할 일

앞서 메뉴 백업이 있는지 확인합니다. 가져오기/내보내기 → 사용자 지정 파일 가져오기 → 방금 만든 이_PC용_메뉴.exportedUI를 선택합니다.

이 작업이 필요한 이유

메뉴 가져오기는 실행 버튼을 배치합니다. XLAM 등록 후 현재 PC 경로로 연결된 메뉴를 가져와야 기능과 버튼이 한 쌍이 됩니다.

생략하거나 다르게 하면

현재 리본·빠른 실행 도구 모음의 사용자 지정이 교체됩니다. 기존 개인 설정도 새 파일 구성으로 바뀌므로 백업을 보관합니다.

완료 기준

매크로 탭에 주 메뉴 24개와 보조 메뉴가 보입니다.
