이 안내의 기준

Windows 데스크톱 Excel과 제공된 통합본 기준입니다. 브라우저용 Excel에서는 VBA를 실행하지 않습니다. 회사 설정에 따라 메뉴 이름이나 매크로 허용 방식이 다를 수 있습니다.

파일을 두 번 클릭하는 것과 달라요

XLAM은 보통 작업 시트처럼 화면에 나타나지 않습니다. 등록된 도구가 뒤에서 준비되고, 실제 데이터는 별도로 연 업무 파일에서 처리합니다.

이 통합본의 에어·부분합·연호 계산은 시험용 데이터로 실행 확인했습니다. 실제 업무 자료 전체 검증과 모든 기존 매크로의 오류 수정이 끝난 파일이라는 뜻은 아닙니다.
01 · UNDERSTAND

업무 파일과 도구 파일을 분리하는 이유

같은 VBA를 주마다 새 파일에 복사하는 일을 줄이기 위한 방식입니다.

매주 파일 안에 VBA를 넣으면

이번 주 파일, 다음 주 파일마다 코드를 넣어야 합니다. 수정한 코드가 어떤 파일에 들어 있는지 헷갈리고, 과거 파일에는 이전 버전이 남기 쉽습니다.

XLAM 하나에 모아두면

공통 VBA는 설치된 한 파일에서 관리합니다. 새 업무 파일을 열어도 같은 리본 버튼으로 실행할 수 있습니다. 코드가 데이터 파일 안에 들어가지 않으면 처리 결과는 보통 XLSX로 저장할 수 있습니다.

작업 파일 자체에 코드·이벤트가 들어 있거나 전용 기능이 필요하면 XLSM을 유지해야 합니다.

형식담는 것이번 사용 방식
.xlsx데이터·수식·서식선박, Air, Balance 등 실제 업무 파일
.xlsm데이터와 VBA특정 파일에 묶인 자동화 또는 개발용 시험 파일
.xlamExcel 추가 기능과 VBA여러 업무 파일에서 반복 사용하는 공통 도구
.basVBA 모듈 하나의 코드새 기능을 XLAM에 가져올 때 사용
.exportedUI리본·빠른 실행 도구 모음 설정버튼의 표시 이름과 실행 연결을 배치

AddIns 폴더여야만 작동하나요?

꼭 그 폴더여야만 하는 것은 아닙니다. Excel 추가 기능 창에서 다른 위치의 XLAM도 찾아 등록할 수 있습니다. 다만 개인용 추가 기능을 한곳에 모으고, 파일을 이동·삭제해 연결이 끊기는 일을 줄이기 위해 AddIns 폴더를 사용합니다.

다운로드 폴더나 매주 바뀌는 업무 폴더보다 고정 위치가 관리하기 편합니다. 이번 메뉴 파일은 기존 AddIns 경로에 연결되어 있으므로 설치 위치와 파일명을 유지하는 것이 특히 중요합니다.

파일 복사 ≠ 추가 기능 등록 ≠ 리본 연결. 폴더에 넣었다고 자동으로 버튼까지 생기지는 않습니다. AddIns에 두는 것만으로 매크로 보안 제한이 해제되는 것도 아닙니다.

Microsoft: 추가 기능 등록 안내 ↗
XLAM은 모든 매크로에 반드시 필요한 형식은 아닙니다. 여러 파일에 반복 적용하는 지금의 업무 방식에 잘 맞는 선택입니다. 파일별 이벤트 자동화는 별도 설계가 필요합니다.
02 · INSTALL

보관 위치를 정하고, Excel에 등록하기

이미 같은 이름의 추가 기능을 쓰고 있다면 기존 파일을 백업한 뒤 교체합니다.

1. 압축 풀기와 기존 파일 백업

  1. 위 통합본 ZIP을 내려받고 압축을 풉니다. ZIP 안에서 XLAM을 직접 실행하지 않습니다.
  2. 열려 있는 Excel 문서를 저장하고 Excel 창을 모두 닫습니다. 실행 중인 추가 기능은 파일을 바꾸기 어렵습니다.
  3. 기존 매크로 신상.xlam을 날짜가 적힌 별도 백업 폴더에 복사합니다. 백업 파일을 추가 기능으로 중복 등록하지 않습니다.

2. AddIns 폴더 열기

Windows 탐색기 주소창 또는 Win + R에 아래 경로를 붙여 넣으세요.

%APPDATA%\Microsoft\AddIns

%APPDATA%는 현재 Windows 사용자의 AppData\Roaming 폴더를 뜻합니다. 다른 사람 PC에서도 사용자 이름을 직접 고칠 필요 없이 폴더를 열 수 있습니다.

압축에서 꺼낸 매크로 신상.xlam을 여기에 넣습니다. 같은 이름의 기존 파일이 있다면 백업 후 교체합니다. 폴더가 없다면 해당 위치에 AddIns 폴더를 만들 수 있습니다.

3. Excel 추가 기능으로 등록

  1. Excel을 켭니다. 파일 → 옵션 → 추가 기능으로 이동합니다.
  2. 창 아래 관리에서 Excel 추가 기능을 선택하고 이동을 누릅니다. COM 추가 기능이나 스토어 추가 기능과 구분합니다.
  3. 찾아보기에서 방금 복사한 매크로 신상.xlam을 선택합니다.
  4. 추가 기능 목록에서 해당 항목을 체크하고 확인합니다. 기존 등록 항목이 같은 경로를 가리키면 체크 상태를 확인하면 됩니다.
  5. Excel을 닫았다가 다시 열고 추가 기능의 체크 상태를 확인합니다. XLAM의 워크시트가 보이지 않아도 이상한 것은 아닙니다.
Microsoft: Excel 추가 기능 ↗
다운로드한 매크로가 차단된 경우

출처를 확인한 ZIP 또는 XLAM의 탐색기 속성에 ‘차단 해제’가 있으면 적용 후 다시 열어보세요. ZIP에 적용했다면 다시 압축을 풉니다. 조직 정책으로 막힌 경우 담당자에게 확인합니다. ‘모든 매크로 사용’을 일괄 선택하는 방식으로 해결하지 않습니다.

‘VBA 프로젝트 개체 모델에 안전하게 액세스’는 다른 프로그램이 VBA 코드를 수정할 때 쓰는 별도 권한입니다. 일반적인 매크로 실행이나 VBA 편집기에서 직접 모듈을 추가하기 위한 필수 설정은 아닙니다.

03 · RIBBON

추가 기능은 엔진, 리본은 실행 버튼

XLAM을 등록한 다음 버튼을 연결합니다. 버튼만 가져오면 VBA 코드까지 설치되는 것은 아닙니다.

추천: 준비된 24개 메뉴 가져오기

  1. Excel에서 파일 → 옵션 → 리본 사용자 지정을 엽니다.
  2. 오른쪽 아래 가져오기/내보내기 → 모든 사용자 지정 내보내기로 현재 메뉴를 먼저 백업합니다.
  3. 가져오기/내보내기 → 사용자 지정 파일 가져오기에서 ZIP에 들어 있는 메뉴_주24개_보조1개.exportedUI를 선택합니다.
  4. 리본의 매크로 탭에서 주 메뉴 24개와 보조 도구의 버튼 만들기를 확인합니다.
  5. 복사한 업무 파일을 열고 대상 시트를 선택한 뒤 필요한 버튼 하나를 시험합니다.
메뉴 가져오기는 기존 리본과 빠른 실행 도구 모음 설정을 교체합니다. 이번 메뉴 파일은 기존 설정을 바탕으로 만들었지만, 이후 직접 바꾼 설정이 있다면 내보내 백업하세요.

제공한 메뉴는 원래 PC의 AddIns 경로를 사용합니다. 다른 PC로 옮기거나 XLAM 이름·위치를 바꾸면 버튼 연결도 새 경로로 맞춰야 합니다. %APPDATA%는 폴더를 여는 편의 경로이며 메뉴 파일 안의 경로가 자동으로 바뀌는 것은 아닙니다.

Microsoft: 리본 사용자 지정과 가져오기 ↗

직접 버튼을 추가하는 경우

  1. 파일 → 옵션 → 리본 사용자 지정에서 오른쪽에 새 탭과 새 그룹을 만듭니다. 기존 사용자 지정 그룹을 써도 됩니다.
  2. 왼쪽 명령 선택을 매크로로 바꿉니다. 원하는 매크로가 보이면 선택하고 추가를 누릅니다.
  3. 이름 바꾸기에서 보기 쉬운 버튼 이름과 아이콘을 정합니다. 표시 이름을 바꿔도 실제 VBA 함수 이름이 바뀌지는 않습니다.
  4. 확인을 누른 뒤 작업 파일에서 실행합니다.
XLAM 안의 매크로는 Excel 버전·노출 방식에 따라 매크로 선택 목록에 나타나지 않을 수 있습니다. 목록에 없다고 코드가 지워진 것은 아닙니다. 기존 24개는 제공한 메뉴 파일로 연결하고, 새 매크로는 아래 ‘새 모듈 추가’ 단계의 메뉴 파일 편집 방법으로 연결할 수 있습니다.

같은 버튼이라도 현재 활성화한 통합문서와 시트에 따라 처리 대상이 달라집니다.

에어_통합정리

Air 데이터가 있는 시트에서 실행합니다. 기본 헤더 FAC / ITEM CD / PURCHASE REQUEST를 먼저 검사하고 열 정리, ADD 표시, 최종 요청 수량 반영, 잔량 계산과 공장별 서식을 함께 적용합니다.

원본 시트 구성이 바뀌므로 처음에는 복사한 파일에서 확인하세요. 별도의 에어_원클릭_정리와는 다른 기능입니다.

연호_입고계산

‘별도 재고 시트를 반영할까요?’에서 예를 누르면 재고 시트의 공장별 수량, 아니오를 누르면 기존 선박 자료의 본사대기를 사용합니다. 취소하면 실행하지 않습니다.

재고 반영을 골랐는데 재고 시트가 없거나 비어 있으면 중단합니다. 연호 ERP·선박·Air·마스터 등 기존 입력 시트도 필요합니다.

부분합_만들기

머리글과 데이터를 포함한 연속 범위를 먼저 선택합니다. 한 기준 또는 두 기준을 고르고 합계 열과 추가 정보 열을 지정합니다.

열 번호는 선택 범위 안에서 센 번호입니다. C:F를 선택했다면 C열이 1번입니다. 추가 정보는 그룹의 첫 행 값을 사용합니다.

품목조회 실행 · V9

대상 파일과 Balance·재고·입고 원본을 같은 Excel 실행 창에서 엽니다. 대상 파일 자체와 추가 기능은 원본 조회 대상에서 제외합니다.

필요한 원본을 못 찾으면 중단합니다. 원본은 읽었지만 개별 품번을 못 찾으면 잔량은 #N/A, 재고·입고는 0이 될 수 있으므로 완료 메시지의 미조회 건수를 확인하세요.

매번 설치해야 하나요?

아니요. 같은 PC에서 등록 상태와 파일 위치가 유지되면 매번 XLAM을 복사하거나 코드를 다시 붙여 넣지 않습니다. 매주 바뀌는 것은 업무 데이터 파일입니다. 다른 PC에는 그 PC에서 추가 기능과 리본 연결을 각각 설정해야 합니다.

05 · KEEP GROWING

새 VBA도 기존 XLAM에 추가하면 됩니다

일반적인 업무 실행 매크로라면 XLAM을 새로 만들 필요가 없습니다. 같은 프로젝트 안에 기능별 표준 모듈을 추가하세요.

직접 추가하는 순서

  1. 설치된 XLAM의 백업을 만듭니다. Excel에서 해당 추가 기능이 등록된 상태인지 확인합니다.
  2. Alt + F11로 VBA 편집기를 엽니다. 프로젝트 창이 없으면 Ctrl + R을 누릅니다.
  3. 왼쪽에서 VBAProject (매크로 신상.xlam)을 선택합니다. 작업 중인 XLSX/XLSM 프로젝트와 혼동하지 않습니다.
  4. 삽입 → 모듈로 표준 모듈을 추가합니다. 속성 창(F4)의 (Name)을 modNewWork처럼 기능별로 지정합니다.
  5. 새 코드를 붙여 넣습니다. BAS 파일을 받은 경우 파일 → 파일 가져오기로 가져오면 모듈이 추가됩니다. 같은 BAS를 두 번 가져오지 않습니다.
  6. 디버그 → VBAProject 컴파일로 문법·이름 충돌을 확인합니다. 오류가 있으면 먼저 해결합니다.
  7. 프로젝트 창에서 XLAM을 선택한 상태로 저장합니다. 필요한 경우 직접 실행 창(Ctrl + G)에서 ThisWorkbook.Save를 실행해 코드가 들어 있는 XLAM을 저장합니다.
  8. 복사한 업무 파일을 대상으로 새 매크로를 시험하고, 리본에 새 버튼을 연결합니다. Excel 재시작 후 저장된 코드와 버튼 연결도 확인합니다.

먼저 ‘처리 대상 확인’으로 연습하기

아래 예제는 선택된 업무 파일과 시트 이름만 보여줍니다. 셀 값은 바꾸지 않습니다. 직접 붙여 넣거나 BAS를 한 번만 가져오세요.

연습용 모듈 받기
Option Explicit

Public Sub 새업무_대상확인()
    Dim wb As Workbook
    Dim ws As Worksheet
    Set wb = Application.ActiveWorkbook
    If wb Is Nothing Then
        MsgBox "작업할 Excel 파일을 먼저 열어주세요."
        Exit Sub
    End If
    If wb Is ThisWorkbook Then Exit Sub
    If TypeName(Application.ActiveSheet) <> "Worksheet" Then
        MsgBox "작업할 워크시트를 선택해주세요."
        Exit Sub
    End If
    Set ws = Application.ActiveSheet
    MsgBox "작업 파일: " & wb.Name & vbCrLf & _
           "작업 시트: " & ws.Name
End Sub

처음 시험할 때는 편집기에서 새업무_대상확인 안에 커서를 두고 F5로 실행할 수 있습니다. 표시되는 파일·시트가 의도한 대상인지 확인한 뒤 실제 처리 코드를 추가하세요.

XLAM에서 특히 중요한 두 이름

표현가리키는 대상쓰는 상황
ThisWorkbook코드가 들어 있는 XLAM추가 기능 자체의 설정·코드를 저장할 때
ActiveWorkbook현재 활성 업무 통합문서지금 선택한 업무 파일을 처리할 때
ActiveSheet현재 활성 시트선택한 시트의 표를 처리할 때

업무 파일을 처리하려는데 ThisWorkbook.Worksheets(...)를 쓰면 XLAM 안에서 시트를 찾게 됩니다. 시작할 때 대상 통합문서·시트를 변수로 잡아두고, 이후 다른 파일을 열더라도 그 대상을 계속 사용하는 편이 안정적입니다.

Microsoft: 추가 기능의 ThisWorkbook과 ActiveWorkbook ↗
모듈 이름·실행 이름·버튼 이름은 서로 다릅니다

모듈 이름 modNewWork는 코드의 묶음, 실행 이름 새업무_대상확인은 Public Sub 이름, 버튼 이름 대상 확인은 리본에 표시되는 글자입니다.

리본에서 쓰는 입구는 Public Sub 새업무_대상확인()처럼 인수 없는 공개 절차로 만들면 관리하기 쉽습니다. 보조 함수는 가능하면 Private으로 두고 기존 공개 실행 이름과 중복되지 않게 합니다. 연결 후 모듈·실행 이름을 바꾸면 버튼 연결도 확인하세요.

새 매크로가 리본의 선택 목록에 안 보일 때

현재 리본을 먼저 .exportedUI로 내보냅니다. 그 파일의 복사본을 텍스트 편집기로 열고, 원하는 사용자 지정 <mso:group> 안에 아래와 같은 버튼을 추가한 뒤 다시 가져옵니다. 기존 버튼 한 줄을 복사해 idQ의 로컬 이름, label, onAction을 각각 새 값으로 바꾸는 방법도 가능합니다. idQ는 기존의 매크로 네임스페이스 접두사를 유지하고 로컬 이름은 겹치지 않게 합니다.

<mso:button idQ="x1:NewWorkTargetCheck"
 label="대상 확인" imageMso="ListMacros"
 onAction="C:\Users\사용자이름\AppData\Roaming\Microsoft\AddIns\매크로 신상.xlam!modNewWork.새업무_대상확인"
 visible="true" />

위 경로는 예시입니다. 실제 XLAM 경로로 바꾸고 x1이 내보낸 파일의 매크로 네임스페이스인지 확인해야 합니다. XML에 익숙하지 않다면 새 BAS와 현재 메뉴 내보내기 파일을 함께 보내 메뉴 연결까지 수정하는 편이 편합니다. 새 모듈을 넣었다고 리본 버튼이 자동으로 추가되지는 않습니다.

모든 코드를 표준 모듈에 넣으면 되나요?

아닙니다. 버튼으로 실행하는 일반 업무 VBA는 표준 모듈에 넣습니다. Worksheet_Change 같은 시트 이벤트는 해당 시트 코드에, 사용자 폼은 UserForm에, 클래스 코드는 클래스 모듈에 둡니다. XLAM에서 여러 업무 파일의 이벤트를 감지하려면 Application 이벤트를 연결하는 추가 설계가 필요합니다.

특히 시트에서 복사한 Me.Range 코드를 표준 모듈에 그대로 넣으면 안 됩니다. 외부 라이브러리·시트명·파일 경로에 의존하는 코드도 추가 전에 확인합니다.

06 · MAINTAIN

코드와 메뉴를 한 쌍으로 관리하기

XLAM에는 기능이, 메뉴 파일에는 버튼 연결이 들어 있습니다. 둘을 함께 백업하면 복구하기 쉽습니다.

앞으로 업데이트할 때

  1. 기능을 수정하기 전 XLAM을 날짜별로 백업하고, 리본 설정도 내보냅니다.
  2. 배포 파일로 교체할 때는 Excel을 모두 닫고 기존 설치 위치의 파일을 교체합니다. 새 버전 번호는 백업 폴더나 변경 기록에 적고, 등록된 파일명·경로는 유지하는 편이 편합니다.
  3. Excel을 다시 열어 추가 기능 등록 상태를 확인합니다. 기존 모듈·실행 이름이 같으면 버튼 연결을 유지할 수 있습니다. 이름·경로가 바뀌었다면 다시 연결합니다.
  4. 새 기능을 더한 경우 기존 기능 하나와 새 기능을 각각 시험합니다. 문제가 생기면 Excel을 종료하고 백업 XLAM과 메뉴 설정으로 되돌립니다.
증상먼저 확인할 것
XLAM을 열었는데 아무 시트도 안 보임추가 기능은 숨겨진 상태로 로드될 수 있습니다. 추가 기능 체크 상태와 리본 실행을 확인합니다.
‘매크로를 실행할 수 없습니다’XLAM 등록·파일 경로·매크로 허용 여부와 버튼의 모듈/실행 이름을 확인합니다.
버튼은 있는데 다른 파일을 처리함업무 파일과 대상 시트를 다시 선택합니다. 코드의 ActiveWorkbook/ThisWorkbook 사용도 확인합니다.
새 코드를 넣었는데 버튼이 없음코드 추가와 메뉴 추가는 별도입니다. 기존 리본 설정에 새 실행 이름을 연결합니다.
예전 기능이나 중복된 이름이 보임구버전 XLAM을 함께 등록했는지, 동일 BAS를 여러 번 가져왔는지 확인합니다. 사용 중인 파일은 확인 없이 지우지 않습니다.
저장 후 재시작하니 새 코드가 사라짐다른 프로젝트를 편집했거나 XLAM이 읽기 전용인지 확인합니다. 설치된 XLAM을 선택해 저장합니다.
‘이름이 분명하지 않습니다’ 또는 컴파일 오류같은 공개 Sub/Function 중복, 누락된 보조 함수, 표준 모듈에 들어간 시트 이벤트 코드를 확인합니다.
V9 원본을 못 찾음대상과 원본을 같은 Excel 실행 창에서 열고 파일명·헤더·공장 정보를 확인합니다.
